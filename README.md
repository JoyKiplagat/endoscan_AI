# EndoScan AI

An AI-assisted triage and explanation tool for endometriosis. Built around a hard
distinction that shapes the whole architecture: **some paths score severity,
others only explain an existing scan** — and the two are never allowed to blur
into each other.

---

## 1. Architecture

```
DIAGNOSTIC / SCORING LAYER  (produces an ESI tier: Low / Moderate / High / Critical)
  Structured questionnaire  ──► LightGBM + Platt calibration ──► esi_score, esi_tier ─┐
  Free-text symptom input   ──► BioBERT NER + alias/semantic  ──► score, tier         ─┼─► fuse_esi() ─► final_tier
                                matching + rules-based scoring                        ─┘

COMPLEMENTARY EXPLAINER LAYER  (never scores, never feeds the tier above)
  MRI scan       ──► EfficientNet-B0 ──► finding + confidence + Grad-CAM ──► Gemini ──► plain-language explanation
  Laparoscopy    ──► EfficientNet-B0 ──► finding + confidence + Grad-CAM ──► Gemini ──► plain-language explanation
  (routed automatically by image type — see endoscan_scan_router.ipynb)
```

**Why the split matters:** the explainer layer is only offered to patients who
are *already diagnosed* and want an existing scan explained in plain language.
It must never influence or feed into the severity score computed by the
diagnostic layer above — that boundary was a deliberate architectural fix made
partway through this project (the MRI notebook originally treated scan
classification as part of the scoring pipeline; it doesn't).

## 3. Diagnostic layer — structured questionnaire path

- **Model:** LightGBM binary classifier → Platt-calibrated probability → `esi_score` (1–100) → `esi_tier`
- **Data:** `endo_data_csv.xls`, ~480,000 records, 12 base symptom/demographic features + 6 engineered features (symptom burden, pain triad score, etc.)
- **Confirmed test-set performance:**

  | Metric | Value | Target | Status |
  |---|---|---|---|
  | AUC | 0.9856 | ≥0.92 | ✓ |
  | F1 | 0.9084 | ≥0.88 | ✓ |
  | Accuracy | 0.9160 | — | — |
  | Recall | 0.9083 | — | — |
  | Precision | 0.9084 | — | — |

- **Output shape:** `{esi_score, esi_tier, probability, description, top_symptoms, family_history, infertility_flag, model_version, path}`

## 4. Diagnostic layer — NLP free-text path

Three-layer pipeline over patient-written symptom descriptions:

1. **Alias matching** — direct phrase lookup against `symptom_aliases.json`, catches informal/patient-voice language
2. **BioBERT NER** (`dmis-lab/biobert-v1.1`, fine-tuned) — catches clinical phrasing and language aliases miss
3. **Semantic mapping** (`all-MiniLM-L6-v2`) — maps NER spans that don't exact-match an alias to the nearest known symptom by embedding similarity
4. **ESI scoring** — a **hand-tuned clinical rules formula** (symptom weight × severity × duration × history modifiers × multi-system bonus), *not* a trained model — see the calibration note in §6

Gemini (`gemini-3.6-flash`) does two jobs: extracting structured fields (symptoms,
severity cues, duration, history flags) from free text, and turning the final
score into a warm, patient-facing explanation.

- **Data:** `synthetic_training_data.csv` + `synthetic_large.csv` (labeled, ~11K rows combined after dedup), plus `pubmed_abstracts`, `forum_data`, and a filtered `mtsamples` subset for unlabeled language support
- **Confirmed test-set NER performance:**

  | Metric | Value | Target | Status |
  |---|---|---|---|
  | Recall | 0.9658 | ≥0.90 | ✓ (primary metric) |
  | Precision | 0.9212 | — | — |
  | F1 | 0.9430 | — | — |
  | F2 | 0.9565 | — | — |

- **Catastrophic forgetting mitigation:** layer-wise learning-rate decay, mixed old/new training batches, recall-weighted loss — documented as a fix for a v1 failure mode where fine-tuning on a small expanded dataset caused the model to lose previously-learned general biomedical knowledge.

## 5. Complementary explainer — MRI

- **Data:** UT-EndoMRI (Zenodo, DOI `10.5281/zenodo.13749613`) — two institutions, `D1_MHS` (Memorial Hermann Hospital System) and `D2_TCPW` (Texas Children's Hospital Pavilion for Women), 92 patients with usable T2-weighted volumes
- **Model:** EfficientNet-B0, last block + head unfrozen, trained with recall as the primary metric (specificity/AUC secondary)

**Key fixes made during development, in order:**

1. **Checkpoint criterion switched from recall to AUC.** Checkpointing on raw recall at a fixed 0.5 threshold picked the *least*-trained epoch (highest recall because it over-predicted positive, not because it discriminated better) — confirmed by a real run where recall fell monotonically while AUC stayed flat. Now checkpoints on validation AUC (threshold-independent), with a separate threshold-tuning pass (Phase 4.6) finding the actual operating point afterward.
2. **Label noise fix (`mri_mask_relabel.ipynb`).** The original slice labels applied one whole-patient diagnosis label to every slice from that patient, including slices with no visible pathology. Re-derived labels directly from the `em` (endometrioma) segmentation mask's presence *in that specific slice*. This is the single biggest fix in the project — AUC moved from ~0.61–0.67 to a stable ~0.83–0.88 after it.
3. **Mask/T2 shape-mismatch bug.** ~40% of `em` masks didn't match their T2 volume's resolution (drawn on a different sequence/grid). The original code silently discarded any mismatched mask; fixed by resampling the mask onto the T2 grid via `nibabel.processing.resample_from_to` instead, recovering real positive-patient coverage (39 → 44 positive patients after the fix).
4. **`cds` (cul-de-sac) structure investigated, not present.** Considered broadening the positive-label criterion to `em` OR `cds` (cul-de-sac obliteration, a marker for deep infiltrating endometriosis not captured by ovarian endometrioma alone) — confirmed via direct file listing that this specific data download contains zero `cds` files. Left in the code as a no-op for documentation; not a bug.
5. **Institution-stratified splitting.** Patient-level train/val/test split stratified by `(institution, label)` jointly (falling back to institution-only when a stratum is too small), to avoid either site or the positive class being accidentally concentrated in one split.
6. **Diverse Grad-CAM sampling.** Originally sampled the first N records per label, which landed on near-identical consecutive slices from a single patient and sometimes boundary-of-scan slices with no diagnostic content. Fixed to sample one slice per distinct patient, preferring the slice with the most lesion evidence for positives.

- **Confirmed test-set performance (real numbers were achieved on real MRI data alone — training data augmentation was defined but never actually regenerated against the corrected v2 labels before this evaluation, so there is real headroom left):**

  | Metric | Value | Target | Status |
  |---|---|---|---|
  | Recall | 0.745 | ≥0.80 | close, not a clean pass |
  | Specificity | 0.743 | ≥0.75 | close, not a clean pass |
  | AUC | 0.836 | ≥0.85 | close, not a clean pass |

  With only 51 positive test slices, these numbers carry wide confidence
  intervals — treat them as directional rather than final.

- **Output:** `explain_mri_scan()` returns a finding + confidence + Grad-CAM
  pointer, explicitly labeled `role: complementary_explainer`,
  `used_by_fusion_layer: False`.

## 6. Complementary explainer — laparoscopy

- **Data:** GLENDA v1.5 (positive/annotated laparoscopy frames) + GLENDA v1.0 `no_pathology` frames (real negatives), split by surgical case ID to prevent same-surgery frames leaking across train/val/test
- **Model:** same EfficientNet-B0 architecture as MRI (last block + head unfrozen)
- **Status: reviewed, has open issues, not fully brought up to the same rigor as MRI:**
  - Negative-class frames are split with a flat random shuffle, **not** by video/case ID the way positives are — same leakage risk that was fixed for positives, still open for negatives
  - Checkpointing on validation loss, not recall or AUC
  - No threshold tuning (flat 0.5) and no probability calibration — `assess_patient.py`/router code account for this explicitly (uncalibrated confidence is shown as a qualitative band, not a raw percentage) but the underlying model itself hasn't been fixed
  - No final test-set metrics were confirmed via an actual run in this project's history — do not report a laparoscopy accuracy number without re-running its evaluation cell

## 7. Scan router (`endoscan_scan_router.ipynb`)

Single entry point for an uploaded scan image:

1. **Modality detection** — not a trained classifier. Uses a cheap, inspectable
   heuristic: MRI PNGs are saved as grayscale (R=G=B per pixel), laparoscopy
   frames are real color video with genuine channel variation. Mean
   channel-difference above a threshold → laparoscopy, below → MRI.
2. **Routing** — `MODALITY_CONFIG` holds the model, threshold, calibrator, and
   Grad-CAM target layer per modality; adding ultrasound later means adding
   one entry there.
3. **Explanation** — one shared Gemini prompt template for both modalities,
   parameterized by `scan_description` rather than duplicated per modality.

## 8. Fusion logic (`assess_patient.py`)

`fuse_esi()` combines the structured and NLP diagnostic results by **tier**,
not by averaging raw scores. This was a deliberate choice, not a shortcut:
the structured path's score is a calibrated ML probability; the NLP path's
score is a hand-tuned rules formula normalized against an arbitrary ceiling.
Both happen to range 1–100, but they are not statistically comparable —
averaging them would let whichever path's number is numerically larger
dominate regardless of actual clinical agreement. The more severe of the two
tiers wins, consistent with the system's stated "missing a case is worse than
a false alarm" philosophy (and the NLP scorer's own internal auto-escalation
logic).

`_build_fused_explanation()` generates a single explanation narrative from the
*actual fused tier*, rather than reusing one path's self-contained narrative —
an earlier version of this code reused the NLP path's Gemini explanation
verbatim, which could (and once did, in testing) describe a different tier
than the one actually returned to the patient.

## 9. Known limitations / next steps

- **NLP score is not yet calibrated.** The rules-based formula has only been
  validated against six hand-written synthetic test cases (internal
  consistency), not against real outcome data. `synthetic_training_data.csv`
  / `synthetic_large.csv` both carry a real `esi_label` column that could be
  used to Platt-scale the NLP score the same way the structured path's
  probability was calibrated — once that's done, `fuse_esi()` could move from
  tier-comparison to a real probability-weighted average.
- **Laparoscopy model needs the same rigor pass MRI already got** — case-level
  negative split, recall/AUC-based checkpointing, threshold tuning,
  calibration. See §6.
- **MRI recall (0.745) is short of target** — regenerating the augmented
  training set against the corrected v2 mask-derived labels (defined but
  never actually used in the run that produced the confirmed numbers above)
  is the most promising next lever.
- **Gemini model names churn.** `gemini-2.5-*` is scheduled to shut down
  October 2026; `gemini-3.6-flash` is confirmed working as of this project.
  Check `genai.list_models()` before hardcoding a model name in future work.
- **API key hygiene.** A Gemini key was exposed in plaintext during
  development — rotate it in Google AI Studio if that hasn't already been
  done, and load keys from an environment variable everywhere (as
  `structured_model.py` / `nlp_model.py` already do), never hardcoded.
- **Presentation deck's dashboard link is still a placeholder** — needs a real
  URL before the deck is finalized.
- **Ultrasound is not yet a supported modality** — no data currently exists
  for it; the router is structured so it's a one-entry addition to
  `MODALITY_CONFIG` once it does.

## 10. Running this locally

```bash
conda activate ds_study   # or your equivalent environment with lightgbm,
                          # torch, transformers, sentence-transformers installed

export GEMINI_API_KEY="your-key-here"   # required by nlp_model.py and the scan router

python structured_model.py   # smoke-tests the structured path in isolation
python nlp_model.py          # smoke-tests the NLP path in isolation

python -c "
from assess_patient import assess_patient
result = assess_patient(
    questionnaire_input={...},   # see structured_model.py FEATURES for the expected keys
    free_text_input='...'
)
print(result)
"
```

Update the path constants at the top of `structured_model.py` and
`nlp_model.py` (`ARTIFACTS_DIR`, `DATA_DIR`, `NER_MODEL_DIR`) to match where
your trained checkpoints actually live.
